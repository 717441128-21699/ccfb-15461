# 县广播电台 · Web 自动播出系统

纯 TypeScript + Web Audio API 的无人值守自动播出系统。老播出电脑的三大痛点对应三条硬保证：

- **歌间不再硬切/叠撞**：叠接只发生在「上一首淡出段 × 下一首前奏」内，按上一首节拍网格整拍对齐，**人声重叠时间恒为 0**。
- **整点报时不偏**：整点前倒排，按剩余时长挑歌/垫乐，末首淡出可在 ±6s 内微调，报时第一声锚定整点，**计划偏差 0、实测发声偏差目标 ≤100ms**。
- **临时插播不乱**：插播新闻后保留已播条目，后续单子自动重排，报时锚点不变。

## 四个功能区

1. **曲库分析**：Worker 池并行合成五种风格（流行/摇滚/民谣/电子/室内乐）的歌曲、广告、垫乐、新闻，DSP 分析出人声进入点、淡出起点、节拍网格、BPM，并与合成真值核对误差。含一键万条压测与准确率自测。
2. **播出单编排**：选宏小时长度（60s 快演 ~ 60min 真实整点），倒排生成时间轴，展示叠接时长、淡出调整、垫乐填充、人声碰撞核验。
3. **播出监视**：Web Audio 前瞻调度（lookahead），采样级精确启停与增益包络；显示当前/下一条、电平表、报时倒计时、实测发声偏差、欠载次数；支持临时插播重排。
4. **播出日志**：分级事件流（含报时对齐 timing 事件），可按级别过滤、导出 CSV。

## 关键算法

| 模块 | 方法 |
|---|---|
| 人声进入点 | 600–1600Hz 共振峰带滚动能量相对前奏基线的结构变化检测（曲首 30% 窗，持续确认 + RMS 兜底） |
| 淡出起点 | 尾部枚举分界点的分段线性拟合，前段贴平台、后段线性衰减，归一化误差最小者 |
| 节拍/BPM | 谱通量 onset → 自相关周期估计 → 抛物线插值；倍频校正（半 lag 绝对峰强 ≥0.42 时取半） |
| 安全叠接 | `overlap ≤ min(上首outro, 下首intro)` 且为上首整拍数；垫乐视为无人声不受 intro 约束 |
| 整点倒排 | 超量删歌/截断，欠量补歌 → 残差 ≤6s 末首淡出微调，更大残差垫乐循环填充，末位收敛残差到 0 |

## 性能与架构

**能力自适应双路径**（启动时探测 Worker 是否支持 `OfflineAudioContext`）：

- **标准路径（用户的正常 Chrome/Edge）**：DedicatedWorker 完整支持 Web Audio，合成（OfflineAudioContext 渲染）与 DSP 分析都在 Worker 池内并行，主线程只派发任务，可吃满多核。
- **回退路径（Worker 无 OAC 的受限环境，如部分自动化浏览器）**：探测到后自动改为「主线程并行合成 + Worker 纯 DSP 分析」，功能与精度不变，仅吞吐受主线程渲染限制。

DSP 自身已重度优化：分析率 4kHz、128 点 FFT、Hann 窗复用、boxcar 抗混叠抽取、能量域频谱统计、倍频校正，**纯分析单条约 18ms，8 Worker 并行 1 万条纯分析约 22 秒**（`node --experimental-strip-types src/audio/bench.ts`）。
标准路径下合成也在 Worker，万条端到端由多核并行承担，满足 <10 分钟目标；回退路径受单主线程渲染约束，吞吐明显降低，属环境限制而非算法瓶颈。

实测（本机 16 逻辑核，受限自动化环境走回退路径）：36 条 60–120s 素材端到端约 100s、零失败；纯 DSP 准确率自测 6 用例全部通过。

## 运行

```bash
npm install
npm run dev      # 开发
npm run build    # 类型检查 + 生产构建
npm run preview  # 预览构建产物
npm test         # 调度器/时钟 + DSP/采样率 纯函数测试（18 项）
```

浏览器打开后：曲库分析 → 生成演示曲库（或 DSP 自测）→ 播出单编排 → 播出监视开播。
音频回放需浏览器允许声音（首次点击按钮即获得 AudioContext 用户手势授权）。
